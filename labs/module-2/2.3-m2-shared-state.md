# 2.3 — The problem with local state

How can Pod 3 read a value written by Pod 1?

## Investigate

1. Watch the animation. The first request writes a preference through Pod 1; a later connection reaches Pod 3 and reads the same value.
2. Test one claim in your local environment. Capture the command, result, and any failure.
3. Compare the observation with the evidence target. Explain what remains unproven.

## Evidence target

A state value written by Pod 1 can be read by Pod 3; a stateless request need not touch Valkey.

## Check your work

Use the `cluster` vet check and the load harness. Scaling behavior and HPA convergence require your own timed observations.

A passing automated check covers the named observations only. Use [the evidence rubric](../../docs/evidence-rubric.md) for the rest of this lesson’s claim.

## If the result differs

Only requests needing state access Valkey. A health request can be answered entirely by an API Pod.
