# 4.3 — Capabilities + seccomp

Why was the forbidden action blocked—capability, syscall filter, or another control?

## Investigate

1. Inspect the workload’s capabilities and effective syscall profile.
2. Apply narrower capability and syscall restrictions suited to the workload.
3. Exercise a chosen disallowed privileged operation, then exercise the normal API path.

## Evidence target

Recorded capability/seccomp configuration plus one policy-relevant denial and one successful application request.

## Check your work

Use the `security` vet check for a running Podman container. Admission, scan, SBOM and trust claims need the separate artifact/evidence rubric.

A passing automated check covers the named observations only. Use [the evidence rubric](../../docs/evidence-rubric.md) for the rest of this lesson’s claim.

## If the result differs

Preserve the exact error, inspect the workload and its events, then change one variable at a time.
