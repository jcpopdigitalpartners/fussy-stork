# 4.8 — Secure and still useful

Which unverified claim would most weaken your release recommendation?

## Investigate

1. Create a test matrix of intended operations and operations that must be denied.
2. Run both sets against the same deployed digest and capture the actual outcomes.
3. Submit a concise pull-request summary linking configuration, scan, SBOM, verification, and test evidence.

## Evidence target

Reviewable PR summary: tested digest, positive and negative outcomes, artifacts, residual risks, and links to raw evidence.

## Check your work

Use the `security` vet check for a running Podman container. Admission, scan, SBOM and trust claims need the separate artifact/evidence rubric.

A passing automated check covers the named observations only. Use [the evidence rubric](../../docs/evidence-rubric.md) for the rest of this lesson’s claim.

## If the result differs

Preserve the exact error, inspect the workload and its events, then change one variable at a time.
