# 4.7 — Name, verify, then run

What is the exact trust claim you checked, and what could still be missing?

## Investigate

1. Resolve the release image to a digest and compare it with the artifact you reviewed.
2. State the trust policy: the artifact digest, verification method, and identity or public key you expect. Verify the signed artifact against that policy.
3. Record the signer or key check, artifact identity, and decision to accept or reject deployment.

## Evidence target

Pinned image digest, verification output or documented expected failure, and an explicit trusted identity/key criterion.

## Check your work

Use the `security` vet check for a running Podman container. Admission, scan, SBOM and trust claims need the separate artifact/evidence rubric.

A passing automated check covers the named observations only. Use [the evidence rubric](../../docs/evidence-rubric.md) for the rest of this lesson’s claim.

## If the result differs

Preserve the exact error, inspect the workload and its events, then change one variable at a time.
