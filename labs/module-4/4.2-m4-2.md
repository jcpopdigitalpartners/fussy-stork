# 4.2 — Make the root filesystem read-only

Which path must remain writable, for how long, and who should own it?

## Investigate

1. Inspect where the API writes temporary files and any persistent state.
2. Configure the root filesystem boundary and provide only the required writable surfaces.
3. Demonstrate a denied write on the image filesystem and successful intended writes, then retest the API.

## Evidence target

A mount or filesystem description, one expected read-only denial, one allowed bounded write, and a passing API check.

## Check your work

Use the `security` vet check for a running Podman container. Admission, scan, SBOM and trust claims need the separate artifact/evidence rubric.

A passing automated check covers the named observations only. Use [the evidence rubric](../../docs/evidence-rubric.md) for the rest of this lesson’s claim.

## If the result differs

Preserve the exact error, inspect the workload and its events, then change one variable at a time.
