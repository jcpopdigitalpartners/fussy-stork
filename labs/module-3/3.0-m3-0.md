# 3.0 — When a working system fails

If an API Pod disappears, which parts of the system can actually recover?

## Investigate

1. Sketch three failure consequences: an interrupted request, a replacement Pod, and an unavailable datastore.
2. Test one claim in your local environment. Capture the command, result, and any failure.
3. Compare the observation with the evidence target. Explain what remains unproven.

## Evidence target

The Pod controller may restore the desired replica count, but application success and data safety require separate evidence.

## Check your work

Capture an `api` vet report before a fault, then rerun with `--baseline` after recovery. Complete the recovery evidence rubric.

A passing automated check covers the named observations only. Use [the evidence rubric](../../docs/evidence-rubric.md) for the rest of this lesson’s claim.

## If the result differs

Compare requests and database behavior from the client perspective. Ready is one signal, not a complete recovery test.
