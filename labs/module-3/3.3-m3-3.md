# 3.3 — Persistence is not a backup

What evidence shows that the backup can restore useful data?

## Investigate

1. Design a disposable target database and a known record-count check. Predict what a backup cannot undo about a subsequent bad write.
2. Test one claim in your local environment. Capture the command, result, and any failure.
3. Compare the observation with the evidence target. Explain what remains unproven.

## Evidence target

Restored data is independently queryable and meets an explicitly stated expected result.

## Check your work

Capture an `api` vet report before a fault, then rerun with `--baseline` after recovery. Complete the recovery evidence rubric.

A passing automated check covers the named observations only. Use [the evidence rubric](../../docs/evidence-rubric.md) for the rest of this lesson’s claim.

## If the result differs

Treat a file as unverified until it is restored to a separate environment and inspected. Check dump format and tool compatibility.
