# 3.7 — Break it deliberately

What failure would best reveal a weakness in the system?

## Investigate

1. Choose a fault and a prediction, then list evidence from the client, controller, and datastore points of view.
2. Test one claim in your local environment. Capture the command, result, and any failure.
3. Compare the observation with the evidence target. Explain what remains unproven.

## Evidence target

A causal explanation: which condition changed, how it was detected, and how recovery was independently verified.

## Check your work

Capture an `api` vet report before a fault, then rerun with `--baseline` after recovery. Complete the recovery evidence rubric.

A passing automated check covers the named observations only. Use [the evidence rubric](../../docs/evidence-rubric.md) for the rest of this lesson’s claim.

## If the result differs

A single-node cluster can show controller-level recovery, but cannot prove node or storage high availability.
