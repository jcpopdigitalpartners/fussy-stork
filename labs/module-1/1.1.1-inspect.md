# 1.1.1 — Inspect the workload

Which parts of the API need a database?

## Investigate

1. Use docs/baseline-run.md to start the supplied API and its baseline PostgreSQL database. Inspect the source and runtime settings.
2. Compare /health, /ready and /records. Create and retrieve a real record; explain which dependencies each request exercises.
3. Run the api vet check. Review its report, record what remains unproven, and commit your evidence on a task branch.

## Evidence target

The API responds before it is packaged, and its dependencies are documented.

## Check your work

Use `process`, `image`, or `api` vet checks at the appropriate stage. See [solution checks](../../docs/vetting.md).

A passing automated check covers the named observations only. Use [the evidence rubric](../../docs/evidence-rubric.md) for the rest of this lesson’s claim.

## If the result differs

Inspect the DB host, port, connection error, and whether Postgres-QL is actually reachable.
